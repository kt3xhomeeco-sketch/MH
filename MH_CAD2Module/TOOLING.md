0.7.0: worker/plan_learning.py induces measured XY edge/stock-centre anchor programs from the latest accepted manual plan result per geometry signature. Three distinct signatures, matching input construction topology/stock/output grouping and zero leave-one-signature-out failures are required. All viable anchor expressions must agree on a target; true CAD circle evidence confirms inferred circular profiles. Exact plan feedback has priority. Partial, excluded, incompatible parser and malformed records do not activate a rule. Parser/schema/source digests and catalog checksums invalidate caches; immutable checksum revisions preserve derived rule history. The latest accepted source records remain untouched.

plan_rules.rb queues one background worker per pending library after saved acknowledgement; a learning failure cannot revoke acceptance. The native thread reads status.json only, never compiles the corpus. Worker action learn_plan supports the accepted product's resolved library independently of the current job folder. test/test_plan_rules.py, test/plan_rules_test.rb and tools/plan_rules_ui_check.cjs cover activation, held-out/unseen geometry, stock/topology, conflicts, exclusion, cache/parser invalidation, actual scan routing, source placement, arcs, queue deduplication/failure and UI provenance/status. tools/plan_rule_native_fixture.py creates synthetic data only under outputs/l; tools/native_plan_rules_check.rb verifies unseen straight/curved native solids, R140 ArcCurves, independent Groups and frame placement in one aborted operation. The flat-group native regression stubs background training and asserts one queue request after successful acceptance. Real-library refresh only writes derived rules/status and a normal background job; it does not add accepted samples or alter model geometry.
