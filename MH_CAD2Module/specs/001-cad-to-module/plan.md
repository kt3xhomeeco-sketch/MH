# Implementation Plan: MH CAD2Module
Date: 2026-10-18. Feature: specs/001-cad-to-module/spec.md. No branch switch.

## Summary
SketchUp plugin is the main UI. A Python worker archives DWG/DXF and extracts geometry using ODA+ezdxf. Rule-based panel recognition produces evidenced carcass boxes. Ruby builds a centred product assembly. Correction mode records transactions and independent SKP snapshots; exact structural examples may be replayed.

## Technical Context
Ruby 3.2 / SketchUp 2025; Python 3.12 / ezdxf 1.4.3 / openpyxl; HTML/CSS/JS HtmlDialog. Filesystem library defaults to the app-local library/ directory; relocation preserves prior data. Windows process jobs use hidden spawn with request files and UI timer polling. Testing: pytest, Ruby minitest, RuboCop/rubocop-sketchup, native SketchUp aborted operations. CAD previews are vector canvas, no remote service.

## Constitution Check
PASS: geometry-only dimensions; global-axis placement; immutable library; explicit ambiguity; scoped edits; measured correction evidence. Post-design PASS. No extension hooks registered.

## Project Structure
Root loader ../MH_CAD2Module.rb. Runtime: main.rb, settings.rb, jobs.rb, model.rb, storage.rb, corrections.rb, templates.rb, ui/, worker/. Dev-only: test/, tools/, .agents/, .specify/, specs/.

## Design
See research.md, data-model.md, contracts/worker.md and quickstart.md. Main hazards: unknown depth, duplicated views, unsafe template scale, correction undo and file races. Guard them with evidence checks, content-addressed snapshots, exact structural matching and named model operations.
