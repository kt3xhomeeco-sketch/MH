# Worker contract
UTF-8 request/response JSON files under library/jobs/UUID. Ruby spawns Python with argv, not a shell. Request: action analyze|products, library, sources or Excel path, optional converter. Response: ok, analyses/products, errors. Analysis has modules in mm, view outlines, evidence and source revision. No Python references to SketchUp objects.

Correction events: schema=1, UUID/time, session, analysis source hash/signature, before, after, reason, snapshot paths and status. Writes are atomic. Generated component snapshots are separate SKP files, never a save-over of the active model.

Stage request fields: build_plan boolean (default true), build_elevation boolean (default false). Elevation requires plan; no plan is an explicit error. Products carry build_stages={plan,elevation}. Plan-only products have geometry_pipeline.mode=plan_only, default_height_mm=1600 and height_source=provisional_default, with no horizontal stage. Full-layout learning is bypassed (learning.mode=staged). Cache names include plan1600/full. A correction whose analysis.build_stages.elevation is false is excluded from full-height example replay.

Direct selected-geometry requests carry plane=XY|XZ|YZ and plane_offset_mm. Ready products carry placement={mode:source_plan,plane,origin_mm:[u,v],plane_offset_mm}. Native construction maps this source-plane basis to world coordinates instead of consulting labels. Absent legacy offsets default to zero; new capture hashes include plane/offset. Plan-only 50 mm auxiliary strips retain original_depth_mm=50 and their source plan_box while solid_proxy=true and depth_evidence identify the adjacent cabinet front/back planes used for proxy depth.

Learning runs after cached analysis for DWG/DXF and selected SketchUp edges. Product.learning exposes mode, source_code/event and diagnostic issues; Product.experience retains the history file reference. On similar matches, each part carries anchor_evidence for X0/X1/Y0/Y1/Z0/Z1 with current target view IDs, target handles, CAD coordinates and calibrated view origins. Product.geometry_pipeline.mode is learned_measured_anchors. Review states keep error diagnostics and cannot pass Model.build. The extraction parser/cache version remains 0.2.3; extension release is 0.3.0 and derived-rule schema is independent. Accepting a correction makes it available on the next scan; inferred proposals never become accepted events automatically.

Manual correction UI actions (0.5.1): wrong, accept_manual_boxes, cancel_manual_boxes. State.correction adds manual boolean. Acceptance is enabled in an active manual session when idle, reads model.selection at click time, validates before mutation and preserves the session on invalid/empty selection. Only valid captured box instances are hidden. No box-scan action or pending selection IDs. Manual accepted events add input_axes_ignored, manual_source_ids and normalised_from. The plan worker may apply these events at identical signature/version as learning.mode=plan_exact, manual_boxes=true, with every height reset to provisional 1600 and target source_box/plan_box coordinates rebuilt. Otherwise plan learning remains staged. Full-height replay continues to exclude plan-only events.

0.5.2 UI acknowledgement: accept_manual_boxes carries request_id. State.manual_acceptance={status:saved,request_id,code,modules,auxiliary,elapsed_ms} follows durable acceptance; errors return status:error,request_id,message through the existing error publication. Unrelated/stale publications must not clear a different pending request. Beginning a new manual correction or cancelling clears the previous result. This feedback is UI state, not a new training event or change to the worker/storage contract.

0.5.3: acceptance also carries session_id. The lightweight receiveManualAcceptance callback delivers processing/saved/error before full UI publication. manual_acceptance_status(request_id) only returns the latest matching result or {status:unknown,request_id}; it performs no geometry/storage mutation. Duplicate acceptance with the same latest ID echoes its cached result. Client polls at two seconds and shows missing-response feedback at eight seconds; unknown before the deadline is nonterminal. Missing initial bridge fails locally. No automatic acceptance retry is allowed.


0.7.1 native work log: Ruby assigns activity_id to each returned scan product before build, persists scan events and stores activity_id on the live assembly. History index adds activity_id/product_id/session/job_id/automatic_scan/error without modifying original events. State.activities contains collapsed summaries; activity_open(key) loads state.activity_detail with current source analysis and all associated stored events. Row controls carry activity_key for select_activity/select_module/wrong/begin_correction/accept_manual_boxes/cancel_manual_boxes/finish_correction/resize/split/merge/add_module/template. Native routing validates row ownership and correction session; accept preserves model.selection for external boxes. Saved acknowledgements include activity_key; cached duplicate acceptance stays read-only. Root/legacy lookup never guesses between multiple products. Failed-source recovery retains its row identity. Worker recognition and learning contracts remain unchanged.
